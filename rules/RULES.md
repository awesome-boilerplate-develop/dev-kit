# dev-kit rules

Each rule has a status and the lab evidence behind it (the dev-kit lab, private).
Only **on** rules are applied by the controllers. Workflow rules are turned on only if they helped (or cut cost without hurting) on tasks they were **not** written from; rules marked (standard) or (framework) come from published review practice and audits, not from a lab result.

| ID | Rule | Status | Evidence |
|---|---|---|---|
| F1 | **Controller owns the flow.** When a part finishes, continue with the controller's next step; ignore part instructions to stop, hand off or wait for another command. | on | Matt-only controller stalled after diagnosis on B3 (round 2). No stalls with this rule in v0.3/v0.4 runs. Prevents a failure, not a quality gain. |
| F2 | **Finish in this turn.** Run subagents in the foreground and wait for them; never use ScheduleWakeup, Monitor, cron or background waits. The final reply states what was done, the verdict and the report path. | on | 4 of 34 lab runs (v0.4.1–0.6.0) scheduled wakeups to wait for reviewers; in one (P3, 0.6.0) the final reply was "stopped the automatic loop" instead of the verdict, although the report file was complete. |
| C1 | **Default to the direct path.** Do the work in this session; use subagent-driven development only for large work (> 3 tasks or several modules). | on | v0.3 cut story cost 0.463 → 0.062 (S1) and 0.227 → 0.064 (S2) with the same hidden-test results (file 13). |
| C2 | **Review depth.** Small diff (≤ 2 files, < 50 lines): self-review. Otherwise: one reviewer subagent. Four reviewers only when the user asks, or the diff touches auth/permissions, secrets, personal data (including health/medical and patient records), migrations or config/env. Computing prices is **not** a trigger. **Never lower the depth to save cost**; to go lower, ask the user. | on | Baseline found all seeded defects in P1–P3; four reviewers found no more (rounds 1–2). v0.4.0 treated every pricing change as risky and ran four reviewers on almost every card: cost 3–4× baseline with no quality gain. 0.8.2: health data named explicitly after a real review of a patient-prescription PR picked one reviewer. |
| G1 | **Graph tools when indexed:** follow `rules/graph-playbook.md` at the steps that name it — locate code (§2), blast radius (§3), existing tests via CRG `tests_for` (§4), refactor support (§5), module map for large work (§6), review summary via `detect-changes` (§7). CLI only, summaries only — no MCP server, no hooks, no instruction files (file 04 §VII). | on when indexed (opt-in via `dk:init`) | Lab, 17 SWE-bench Django runs each, Haiku 5.5: with indexes 10/17 solved, without 10/17; cost 0.034 vs 0.033 USD/run; agents used the graph (27 codegraph, 33 CRG calls) and grep about half as often (31 vs 58). Neutral: no measured gain or loss. 0.8.0 playbook, same 17 runs with indexes: 12/17 at 0.031 USD/run (0.7: 10/17 at 0.034) — no extra cost, +2 within noise. Kept: opt-in and cheap; revisit with larger repos. |
| B1 | **Known-failure baseline.** If the repo's tests were already red at `dk:init` and the user accepted them, `.dev-kit/baseline.md` lists them; a check passes when nothing fails outside the list. New failures are blockers; never add to the list to make a change pass. | on (standard) | Real repo (Angular MFE, 9,569 specs): 290–303 specs already failing on the base branch; without this, `dk:init` stopped and no controller could run. |
| R1 | **Finding quality gate:** every reviewer applies `standards/review/finding-quality.md` — report only findings introduced by the change, actionable, located, with the condition that triggers them, not intentional, not linter-catchable, citing the rule if any; confidence 0–100; **certain** (≥ 80) counts toward the verdict, **suspect** (50–79) is listed but never blocks. | on (standard) | Learned from Codex review rubric, Claude Code code-review plugin, claude-code-security-review. Measured on the 6-PR backtest (see CHANGELOG 0.8.4). |
| T1 | **Standards:** load kit (`standards.kit` in config), team (`standards.team`) and project (`.dev-kit/standards/`) standards whose `applies_to` matches; project > team > kit; `## Design`/`## Implement` while planning/coding, `## Review`/`## Do not flag`/`## Severity` for the reviewer whose role owns the topic; cite rule ids; an id in `standards.kit` or `standards.disable` with no file is named in the report. Format: `templates/standard.md`. | on (framework) | Design: docs/09. Measured with a team-controls rule on a UI card (CHANGELOG 0.8.7). |
| S1 | **One severity scale:** `blocker` (must fix before merge), `major` (should fix before merge), `minor` (optional). Map other labels: Critical/High → blocker; Important/Medium → major; Minor/Low/Info/Nit → minor. Any open blocker → NO-GO. | on (standard) | Upstream parts used four different scales (file 07 §6 group 8; audit 2026-10-13). |
| O1 | **One personal output home:** dev-kit belongs to one developer and nothing it writes is committed. Everything goes under `.dev-kit/` (`config.yml`, `init-report.md`, `baseline.md`, `standards/`, `specs/`, `plans/`, `reports/`, `sdd/`, and the project knowledge parts produce: `GLOSSARY.md`, `adr/`, `CONSTRAINTS.md`), filled from `templates/`; `.dev-kit/.gitignore` (`*`) keeps the folder out of git. Never edit a tracked file for dev-kit's own bookkeeping: no `.gitignore`, `CLAUDE.md` or `AGENTS.md` changes; ignore local paths in the repo's exclude file (`git rev-parse --git-path info/exclude`; in a worktree `.git` is a file). Reading the project's own `GLOSSARY.md`, `docs/adr/` or `CONSTRAINTS.md` is fine; changes to them are proposed to the user, not made. | on (standard) | Audit 2026-10-13: SDD ledger was in `.superpowers/sdd/`; `code-review` looked for specs outside `.dev-kit/`; `constraint-driven-development` edited `CLAUDE.md` unasked. 1.1.0: `dk:init`, `using-git-worktrees`, `domain-modeling` and `constraint-driven-development` wrote to tracked files that a personal kit must not push. |
| Q1 | **Sibling check:** a new field/parameter must be handled wherever its siblings are (`__repr__`, `__eq__`, `deconstruct`, sync/async twins, docs, tests). | **off (experimental)** | SWE 16560: 6/6 vs 3/6, but written from that task. On 5 unseen tasks: 10/15 vs baseline 11/16 (file 14). Overfit. |
| Q2 | **Read docs/ADRs first; newest accepted decision wins.** | **off (experimental)** | No effect measured: baseline already chose the ADR in S2 (round 2). |

To turn an experimental rule on: run it on its source task and on ≥ 5 unseen tasks of the same kind; keep it only if unseen tasks are not worse than baseline and something improves.
